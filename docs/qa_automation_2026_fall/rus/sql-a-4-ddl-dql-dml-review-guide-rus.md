На предыдущих занятиях студенты работали со готовыми базами данных в режиме чтения [2, 4]. В реальных QA-проектах перед инженером по автоматизации или ручному тестированию часто возникают задачи управления тестовым окружением [3, 26]:
* **Разворачивание тестовых баз «с нуля» (Start from Scratch):** Создание схем и таблиц для изолированного запуска автотестов в CI/CD пайплайнах [26, 38].

## 🧱 3. Теоретический блок: Разбор DDL, DQL, DML с QA-контекстом

### 1. DDL (Data Definition Language) — Язык определения данных
DDL отвечает за работу со **структурой** базы данных и её объектов (базы, схемы, таблицы, колонки) [26, 32].

#### Создание и удаление баз данных [26, 36, 37]:
* `CREATE DATABASE database_name;` (или `CREATE SCHEMA`) — создает новую пустую базу данных [26].
* `DROP DATABASE database_name;` — безвозвратно удаляет базу данных со всеми её таблицами [26].
* **Безопасное выполнение (`IF EXISTS` / `IF NOT EXISTS`) [36, 37, 38]:**  
  ```sql
  DROP DATABASE IF EXISTS mywork;
  CREATE DATABASE IF NOT EXISTS mywork;
  ```  
  *💡 **QA Контекст (Автоматизация тестов):** Использование конструкций `IF EXISTS` критически важно в скриптах автотестов. Если скрипт попытается удалить несуществующую таблицу без `IF EXISTS`, СУБД вернет Error Code и остановит выполнение всего пайплайна [37, 38]. Конструкция `IF EXISTS` превращает фатальную ошибку в предупреждение (Warning) и позволяет скрипту продолжить работу [37, 38].*

#### Создание таблиц (`CREATE TABLE`) и типы данных [27, 28, 29]:
```sql
CREATE TABLE mywork.employee_test (
    employee_id INT NOT NULL,
    hire_date DATE,
    last_name VARCHAR(75),
    first_name VARCHAR(75),
    phone_number VARCHAR(25),
    salary DECIMAL(10,2),
    PRIMARY KEY (employee_id)
);
```
* **Разбор основных типов данных для QA [27, 28]:**
  * **Текстовые (`VARCHAR`, `CHAR`):** Переменная или фиксированная длина строки [27, 28]. *QA Совет:* Если нет уверенности в формате поля (например, телефонные номера с плюсами или дефисами), безопаснее выбирать текстовый тип [28].
  * **Числовые (`INT`, `DECIMAL(p, s)`):** `DECIMAL(10,2)` означает 10 цифр всего, из которых 2 цифры после запятой (идеально для денежных сумм и зарплат, например $10.99) [28, 29].
  * **Даты (`DATE`, `DATETIME`, `TIMESTAMP`):** В MySQL стандартный формат даты записывается строкой `'YYYY-MM-DD'` (например, `'2018-01-01'`) [20, 27].
* **Ограничения целостности (`NOT NULL`, `PRIMARY KEY`) [28, 29]:** `PRIMARY KEY` гарантирует уникальность и непустоту идентификатора записи [28, 29].

#### Модификация структуры таблиц (`ALTER TABLE`) [30, 31, 42, 44, 45]:
* **Добавление колонки:** `ALTER TABLE employee_test ADD COLUMN email VARCHAR(50);` (новое поле добавляется в конец таблицы) [30].
* **Удаление колонки:** `ALTER TABLE employee_test DROP COLUMN email;` [31, 45].
* **Переименование колонки:** `ALTER TABLE EMP RENAME COLUMN job TO job_title;` [42].

---

### 2. DQL (Data Query Language) — Язык выборки данных
DQL отвечает за получение и чтение данных из таблиц [31, 32].
* **Основной оператор:** `SELECT column1, column2 FROM table_name WHERE condition;` [7, 31].
* На этом этапе DQL рассматривается как инструмент валидации результатов выполнения DML-операций (проверка, что вставленная или обновленная строка действительно изменилась) [34, 35, 52].

---

### 3. DML (Data Manipulation Language) — Язык манипулирования данными
DML отвечает за работу с **конкретными записями (строками)** внутри созданных таблиц [32, 35].

#### Вставка данных (`INSERT INTO`) [32, 33, 34, 42]:
```sql
-- Одиночная вставка
INSERT INTO employee_test (employee_id, hire_date, last_name, first_name, phone_number, salary)
VALUES (999999, '2018-01-01', 'Smith', 'John', '555-0199', 100000.00);

-- Пакетная вставка (Batch Insert) нескольких строк
INSERT INTO EMP (empno, ename, job_title, mgr, hiredate, sal, comm, deptno)
VALUES 
(7369, 'SMITH', 'CLERK', 7902, '1980-12-17', 800.00, NULL, 20),
(7499, 'ALLEN', 'SALESMAN', 7698, '1981-02-20', 1600.00, 300.00, 30);
```
* ⚠️ **Главное правило для студентов:** Последовательность колонок в перечне должна строго соответствовать порядку передаваемых значений `VALUES`, а типы данных должны полностью совпадать [33].

#### Обновление данных (`UPDATE`) [34, 35, 43]:
```sql
-- Массовое изменение: повышение зарплаты всем сотрудникам на 10%
UPDATE employee_test SET salary = salary * 1.1;

-- Точечное изменение по условию WHERE
UPDATE EMP SET ename = 'Smith' WHERE ename = 'Polk';
```
* ⚠️ **QA Предупреждение:** Выполнение `UPDATE` без секции `WHERE` приведет к изменению **всех строк** в таблице [34, 35]!

#### Удаление строк (`DELETE`) [35, 43, 44]:
```sql
DELETE FROM EMP WHERE ename = 'Roosevelt';
```

### 4. Сравнение операций очистки: `DROP` vs `DELETE` vs `TRUNCATE`

| Операция | Язык | Что удаляет | Скорость на больших данных (1M+ строк) | Сохранение структуры таблицы | QA Сценарий использования |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`DROP TABLE`** [26, 31, 35] | DDL [31] | Всю таблицу целиком (структуру + данные) [31, 35] | Мгновенно [35] | ❌ Нет (таблица исчезает из БД) [31, 35] | Полное удаление временной таблицы или схемы после завершения тестового прогона [31, 35, 36]. |
| **`DELETE FROM`** [35, 44, 53] | DML [32] | Конкретные строки по условию `WHERE` или все строки [35, 53] | Медленно (каждая строка удаляется и логируется отдельно) [53] | ✅ Да (структура остается) [53] | Точечное удаление созданных автотестом сущностей (`WHERE test_id = 123`) [35, 43, 44]. |
| **`TRUNCATE TABLE`** [53, 54] | DDL [53] | Все строки таблицы (полная очистка) [53, 54] | Очень быстро (освобождает страницы памяти без построчного лога) [53] | ✅ Да (структура и индексы сохраняются) [53, 54] | Быстрый сброс состояния (Teardown) больших справочников или лог-таблиц перед новым прогоном тестов [53, 54]. |

### 5. Связывание таблиц (Primary & Foreign Keys) и реверс-инжиниринг
При связывании таблиц `EMP` (сотрудники) и `dept` (департаменты) через поле `deptno` создается связь «первичный ключ — внешний ключ» [46, 48].

```sql
-- Добавление внешнего ключа
ALTER TABLE EMP 
ADD CONSTRAINT fk_emp_dept 
FOREIGN KEY (deptno) REFERENCES dept(deptno);
```

* ⚠️ **Технический нюанс лекции:** Если попытаться добавить `FOREIGN KEY` на таблицу `EMP`, когда родительская таблица `dept` пуста или не содержит соответствующих ключей, СУБД выдаст ошибку нарушений целостности (Error Code) [47]. Перед связыванием необходимо сначала заполнить родительскую таблицу `dept` [47, 48]!
* **Визуализация в MySQL Workbench (Reverse Engineer):** Через меню `Database -> Reverse Engineer` можно автоматически построить ER-диаграмму (ER Diagram) и визуально проверить связи между `PRIMARY KEY` (иконка ключика) и `FOREIGN KEY` [49].

## 🔮 4. QA Superpower & Вопросы студентов с лекции

во время теории студенты задавали практические вопросы. Ментору следует повторно разобрать их на ревью-сессии:

### ❓ Вопрос 1: «Как найти нужную таблицу и колонку, если база огромная и нет документации?» [22, 23, 24]
* **Сценарий:** Студенту нужно найти должность "President", но он не знает, в какой таблице и колонке хранятся эти данные [22].
* **Решение ментора:**
  1. *Бизнес-логика:* Все должности и роли людей всегда хранятся в таблице сотрудников (`employees` / `EMP`) [23, 24].
  2. *Поиск через метаданные (`INFORMATION_SCHEMA.columns`):* [23]
     ```sql
     SELECT TABLE_NAME, COLUMN_NAME 
     FROM INFORMATION_SCHEMA.columns 
     WHERE TABLE_SCHEMA = 'classicmodels' 
       AND COLUMN_NAME LIKE '%job%';
     ```
     Запрос мгновенно покажет таблицу `employees` и колонку `jobTitle` [23, 24].

---

### ❓ Вопрос 2: «Зачем нужен `IF EXISTS`, если можно просто запустить скрипт ещё раз?» [37, 38]
* **Ответ ментора:** При запуске автоматизированных CI/CD пайплайнов деплоя или прогона автотестов любые ошибки со статусом `Error Code` останавливают выполнение всего билда [37, 38]. Использование `DROP DATABASE IF EXISTS` предотвращает сбой пайплайна, если база данных была удалена ранее [37, 38].

---

### ❓ Вопрос 3: «В чём разница между `DESC` перед таблицей и `DESC` после колонки?» [12, 40, 41]
* **Событие-индикатор:** Двойной функционал ключевого слова `DESC` в MySQL [12, 41]:
  1. `DESC employees;` (сокращение от `DESCRIBE`) — DDL-операция вывода структуры таблицы (список колонок, типы данных, ключи) [9, 12, 40, 41].
  2. `SELECT * FROM payments ORDER BY amount DESC;` — DQL-модификатор сортировки по убыванию (Descending) [12, 19, 41].

## 🔍 6. Типичные ошибки студентов и их решение (Troubleshooting Guide)

### 1. Ошибка «Исчезнувшая схема» после запуска скрипта [14]
* **Симптом:** Студент выполнил скрипт создания базы (`universitydb.sql` или `mywork`), лог показал `Success`, но новая схема не отображается в панели Schemas слева [14, 25].
* **Причина:** MySQL Workbench не обновляет дерево боковой панели в реальном времени [14].
* **Решение ментора:** Напомнить студентам сделать клик правой кнопкой мыши по пустому месту в панели Schemas и выбрать **Refresh All** [14].

### 2. Забытая секция `WHERE` при `UPDATE` или `DELETE` [35]
* **Симптом:** Студент случайно обновил или удалил все записи в таблице вместо одной конкретной [35].
* **Решение ментора:** Научить правилу безопасности QA: *«Сначала напиши `SELECT * FROM table WHERE condition;`, убедись, что выбираются именно нужные строки, а затем замени `SELECT *` на `DELETE` или `UPDATE`»* [35, 50].

### 3. Нарушение порядка аргументов при `INSERT INTO` [33]
* **Симптом:** Ошибка `Incorrect date value` или `Data truncation` при вставке записей [33].
* **Причина:** Несоответствие порядка столбцов в скобках `(col1, col2)` и передаваемых значений в `VALUES (val1, val2)` [33].

### 4. Ошибка добавления `FOREIGN KEY` на незаполненную таблицу [47]
* **Симптом:** СУБД возвращает `Error Code 1215: Cannot add foreign key constraint` [47].
* **Причина:** Попытка связать заполненную дочернюю таблицу `EMP` с пустой родительской таблицей `dept` [47].
* **Решение ментора:** Объяснить порядок заполнения: сначала заполняется родительская таблица (`dept`), и только затем создается и заполняется внешними ключами дочерняя (`EMP`) [47, 48].
